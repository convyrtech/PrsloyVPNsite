# PRSLOY Admin — Access Management (дизайн)

Статус: черновик на утверждение. Автор-контекст: после go-live авто-выдачи через
партнёрский `/external/issue-key`. Цель — превратить админку из пассивной
(«записать вставленную руками ссылку» + тикеты) в реальный пульт управления доступом.

---

## 0. Проблема

Сейчас админка ничего не выдаёт сама:
- `/admin/grant` → `grantAccess(identifier, { subscriptionUrl })` с **вставленной вручную** ссылкой;
- `/admin/reissue` → только тикеты (список заявок + «пометить обработанной»);
- реальную выдачу/перевыпуск оператор делает руками в панели Marzneshin.

С живым `/external/issue-key` это надо автоматизировать: админка должна **выдавать,
продлевать** (сейчас) и **перевыпускать / отзывать / видеть статус** (фаза 2, нужен партнёр).

## 1. Текущее состояние (baseline)

| Что | Где | Делает |
|---|---|---|
| Пользователи | `/admin/users` (AdminUsersClient) | список, поиск, удаление тест-аккаунтов |
| Выдача | `/admin/grant` (AdminGrantClient) → `/api/admin/grant` | ручная вставка `subscriptionUrl` → `grantAccess` |
| Перевыпуск | `/api/admin/reissue` | список тикетов + `markReissueHandled` |
| Аналитика | `/admin/analytics` | воронка/выручка |
| Auth | `lib/admin-auth.ts` | `ADMIN_SECRET`, `isAdminConfigured` / `isAdminAuthorized` |
| Запись о ключе | KV `marzneshin:user:<id>` | `SubscriptionRecord` (marzUsername, issuedAt, periodDays, paymentId, source) — **пишется, но в проде не читается** |

## 2. Роли и доступ

- Одна роль: **оператор** (основатель; партнёр при необходимости). Гейт — `ADMIN_SECRET`.
  Мульти-роль/RBAC сейчас не нужен (KISS).
- Все мутирующие действия — за admin-auth + rate-limit + **аудит-запись**
  (timestamp, действие, target PRSLOY ID, source/reason). «Кто» = единый секрет,
  поэтому фиксируем хотя бы что / кому / когда.

## 3. Экраны (информационная архитектура)

1. **Пользователи** (`/admin/users`) — поиск по email / PRSLOY ID / telegram.
   Колонки: идентичность · статус доступа · есть ключ · статус оплаты · ~срок. Клик → карточка.
2. **Карточка доступа** (эволюция `/admin/grant`) — рабочая лошадка. Показывает текущий
   доступ + ключ + историю + **кнопки действий** (раздел 4).
3. **Очередь перевыпусков** — открытые тикеты; клик ведёт в карточку юзера; действие
   авто-закрывает тикет.
4. **Аналитика** — без изменений.

## 4. Действия (матрица)

| Действие | Механика | Фаза |
|---|---|---|
| **Выдать** | `issueKey(period)` → `grantSubscriptionByUserId`. Комп ОК (без оплаты). | **1 (сейчас)** |
| **Продлить** | `issueKey(новый admin-id, period)` → extend; обновить запись | **1 (сейчас)** |
| **Вставить вручную** | `grantAccess(url)` — фолбэк | есть |
| **Блок / разблок (наша сторона)** | `accessStatus = blocked` — прячет ключ в кабинете | 1 (семантика есть) |
| **Перевыпустить** | партнёрский `/external/rotate-key` → новый url, старый конфиг мёртв | **2 (партнёр)** |
| **Отозвать** | партнёрский `/external/revoke` → выключить marz-юзера + blocked у нас | **2 (партнёр)** |
| **Статус (live)** | партнёрский `/external/status` → срок / трафик / активность | **2 (партнёр)** |
| **Удалить тест-аккаунт** | есть в users | есть |

**Почему перевыпуск — фаза 2:** наш `issue-key` для существующего юзера специально
возвращает **ту же** ссылку (зафиксировано в контракте ради стабильности при продлении).
Rotate/revoke/status — это 3 новых партнёрских эндпоинта.

## 5. Комп-выдача (решение: по email + комп ОК)

- **Вход:** email → резолвим PRSLOY ID (`getUserByEmail`/identity). Нет аккаунта → ошибка
  «юзер сначала создаёт PRSLOY ID» (форма аккаунты не регистрирует).
- **Период:** 1 / 6 / 12 мес (открытый вопрос: нужен ли произвольный N дней).
- **Комп-флаг:** выдача БЕЗ требования подтверждённой оплаты. `source = "manual-grant"`.
- **Синтетический `payment_id`** для `issueKey`: `admin-<hex>` (уникальный → партнёрская
  идемпотентность считает свежей выдачей для юзера → create или extend).
- **Подтверждение в UI** (избежать двойного клика → двойной extend).

## 6. Данные

- Читаем `SubscriptionRecord` — наконец даём ему читателя.
- **Срок (фаза 1)** — приблизительно `issuedAt + periodDays` (после нескольких продлений
  неточно). Точный live-срок — фаза 2 (`/external/status`).
- **Аудит-лог** админ/комп-действий: KV (список или `admin:audit:*`) — что / кому / когда / source / reason.

## 7. Контракт v2 партнёра (фаза 2) — спека

Те же HMAC-правила, что у issue-key (`X-PRSLOY-Signature`, raw body, `secret.strip()`,
lowercase hex, 401/400/5xx, JSON-only, без 429). Полный handoff напишу отдельно (как для
issue-key) после утверждения.

- `POST /external/rotate-key` — `{rotation_id, prsloy_user_id}` → отозвать старый конфиг +
  создать новый → `{marz_username, subscription_url}` (новый url). **Идемпотентность по
  `rotation_id`** (повтор не плодит ещё одну ротацию). 200 new / 409 replay.
- `POST /external/revoke` — `{prsloy_user_id}` → выключить marz-юзера → `{ok:true, status:"revoked"}`.
  Идемпотентно (повтор = тот же результат).
- `POST /external/status` — `{prsloy_user_id}` → `{active, expire_at (UTC ISO), used_traffic_bytes,
  marz_username, subscription_url}`. Read-only.

## 8. Edge cases / guards

- Выдача заблокированному → остаётся blocked (ключ не светим), оператор сначала разблокирует.
- Email без PRSLOY ID → ошибка.
- Двойной клик → confirm + уникальный id (идемпотентность партнёра спасает от дубля юзера,
  но не от двойного extend).
- Комп-выдача — мощно (бесплатные ключи): admin-only + rate-limit + аудит + (опц.) обязательная заметка.
- Ротация на стороне партнёра ОБЯЗАНА убить старый sub — иначе утёкший ключ продолжает жить.

## 9. План сборки

**Фаза 1 (сейчас, ~1–1.5 ч CC):**
- `/api/admin/issue` (POST: email|userId, period, comp-флаг) → `issueKey` → `grant` → запись + аудит +
  авто-закрытие тикета, если был.
- Карточка доступа в AdminGrantClient: поиск по email → статус/ключ/история → кнопки
  **Выдать / Продлить / Вставить вручную / Блок**.
- Очередь перевыпусков с кнопкой «Выдать» прямо из тикета.
- Тесты (route + idempotency) + i18n (RU/EN).

**Фаза 2 (нужен партнёр):**
- handoff на rotate/revoke/status → партнёр делает → вшиваю кнопки
  **Перевыпустить / Отозвать / Статус (live)**.

## 10. Решения (зафиксировано)

1. **Период выдачи** — кнопки 1 / 6 / 12 мес **+ поле «произвольно N дней»** (для компов: триал 7 дней, извинение 3 дня и т.п.).
2. **Аудит-лог** — **да, сразу**. Каждое админ-действие пишет запись (ts / action / target PRSLOY ID / period / source / note).
3. **«Отозвать» до фазы 2** — **нет полу-мер.** В Фазе 1 только честная кнопка **«Заблокировать (скрыть у себя)»** (`accessStatus=blocked`: прячет ключ в кабинете, но конфиг в Marzneshin ещё жив — утёкшая ссылка работает). Настоящий **«Отозвать»** (убивает конфиг) = Фаза 2 (`/external/revoke`).
4. **Комп-выдача** — **заметка/причина обязательна** при бесплатной выдаче (привязана к аудиту). Для оплаченной — необязательна.
