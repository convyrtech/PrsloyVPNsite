## Как читаем конфиг
Из каждого ключа достаём НЕ сервера, а **приёмы**. Колонки матрицы ниже — это и есть чек-лист «что выдернуть».

## Разбор по конфигам

### Config 1 — AmoreSZI (`szi.amoretech.pro`)
- **Статус: ключ активен** (`download≈28 МБ` после активации), НО sub **всё равно отдаёт болванку** `0.0.0.0 #Не поддерживается` даже под Happ-UA. Это не «нет доступа» — это **жёсткий Happ-lock / анти-скрейп**: реальные ноды отдаются только настоящему приложению Happ (и/или с РФ-IP); curl с любым UA получает заглушку. Сильная защита экзит-IP от парсеров.
- **Качество (тест AI Studio): FAIL** — Google AI Studio через них не открывается → экзиты на засвеченных/дата-центровых IP. Прямая слабость; наш козырь — чистые IP.
- **Панель: Remnawave** (правило `MATCH,→ Remnawave`). Сервер: Caddy. Современная панель управления xray/vless (конкурент Marzneshin).
- **Happ-интеграция (продуктовый приём):** заголовки `Announce` (баннер-объявление в приложении), `Profile-Title`, `Profile-Update-Interval: 2` (автообновление подписки раз в 2ч), `Profile-Web-Page-Url`, ссылка на саппорт-бота. Богатый брендинг внутри клиента.
- **Подача:** называют себя «сервис защиты соединения», не «VPN» (РФ-юр-грамотно). UX-деталь: при отсутствии доступа показывают именованную ноду-сообщение, а не пустой конфиг.
- **Дефолты шаблона:** `client-fingerprint: chrome`, `packet-encoding: xudp`.
- **Доставка:** base64-sub (v2ray-формат) для большинства UA; полный **clash-YAML** для clash-клиентов. UA-зависимая отдача.
- **✅ Реальный конфиг (экспорт из Happ), нода «🇨🇭 Швейцария»:**
  - **Стек: VLESS + XHTTP + Reality**, fp `chrome`, без flow (xhttp его не использует), mux выкл, `packet-encoding: xudp`.
  - **Exit:** `103.227.84.107:443` → MHost LLC, AS200823, Zurich CH. По гео реально Швейцария, НО ip-api помечает IP как **`proxy: true`** (засвечен в анти-прокси-листах) → вот почему AI Studio/ChatGPT режут. Корень провала — грязный IP, а не страна.
  - **Reality dest (SNI): `www.samsumg.com`** — опечатка «samsung», и домен **не резолвится (REFUSED)**. Косить под несуществующий домен = слабая маскировка + риск активного детекта. У нас dest обязан быть реальный, популярный, резолвящийся, РФ-доступный сайт.
  - **XHTTP:** path `/berketgo`, mode `auto`, чанкование upload (`scMaxConcurrentPosts 10`, `scMaxEachPostBytes 1MB`, `scMinPostsIntervalMs 30`).
  - **DNS:** DoH; Google `8.8.8.8` → **через туннель** (анти-лик), Yandex `77.88.8.8` → **direct** (скорость для РФ); `queryStrategy UseIPv4`. Домены налоговой `lkfl2/lknpd.nalog.ru` **прибиты к реальным IP Ростелекома** (`213.24.64.175/181`, проверено — анти-poisoning), НО в роутинге direct для них не прописан → поедут через Швейцарию → для РФ-госуслуг, скорее всего, сломано. Недоделка.
  - **Роутинг:** по сути **full-tunnel** — нет `geoip:ru` direct, нет блока рекламы; direct только LAN/private + Yandex-DoH. Все РФ-сайты идут через швейцарский (грязный) IP — медленно и палевно.

### Config 2 — «DE-запасной» (другой сервис, юзер гонял ~месяц)
- **Уровень заметно выше #1** — опытная рука на транспорте и роутинге.
- **Стек:** VLESS + **XHTTP (`stream-one`)** + Reality, fp **`qq`** (не chrome), mux вкл (`xudpProxyUDP443: reject` — режут QUIC-over-mux).
- **Exit:** `87.120.84.255:443` → Frankfurt, Neterra/Play2go (AS215439). Опять **`proxy:true`** — тоже засвечен → тоже валит AI Studio. (Ровно твоё «серверы отваливаются».)
- **Reality dest: `user.cdn-ui.info`** → резолвится в их же IP (свой домен, рег. через timeweb.ru). Лучше #1 (резолвится, единая легенда), но домен низкорепутационный — слабее, чем косить под гиганта.
- **XHTTP — экспертный тюнинг (reference, если внедряем):** path `/api/v2/updates` (маскировка под app-API), **`xPaddingBytes 100-1000`** (рандом-паддинг против DPI по размерам), `scStreamUpServerSecs 20-80`, **`xmux`** с рандом-диапазонами реюза (`hMaxRequestTimes 600-900`, `maxConcurrency 16-32`) — косит под обычный keep-alive HTTP.
- **DNS:** split — Yandex DoH для `.ru/.su`, Google по умолчанию, Cloudflare фолбэк.
- **Роутинг — ЗОЛОТО, копировать целиком:**
  - **block:** bittorrent (бережёт exit-IP от абуз/DMCA).
  - **force-proxy (заблок. в РФ):** OpenAI/Claude/Anthropic/Gemini, Telegram (+ IP-блоки 91.108/149.154), YouTube, Discord, WhatsApp, GitHub.
  - **direct (РФ — скорость + родной IP):** курированный список — `.ru/.su`, банки (Сбер/Тинькофф/Альфа/ВТБ/Райф/ЦБ), госуслуги/налог, маркетплейсы (Ozon/WB/Avito/Lamoda/DNS/Мвидео), телеком (Билайн/МТС/Мегафон), стриминг (Кинопоиск/ivi/rutube), vk/yandex/mail, hh, 2gis, whoer.
  - LAN → direct.

### Config 3 — **Liberty VPN** (сильно рекламится, 2 рекомендации; конфиг «Авто-выбор»)
**Productized версия НАШЕЙ архитектуры (цепочка) + авто-балансер. Самый зрелый — это наш эталон/чертёж.**
- **Архитектура = chain:** у каждого экзита ДВА outbound'а — `-direct` (клиент→иностр. exit) и `-bypass` (`sockopt.dialerProxy` → upstream-SOCKS → иностр. exit). Ровно «RU-bridge → foreign-exit через dialerProxy», как у нас.
- **Авто-балансер** (`routing.balancers`, `leastLoad`): health-check пингом `gstatic/generate_204` каждые 2м, `maxRTT 1500ms`, **costs: bypass ×3** → предпочитает direct, на bypass-цепочку падает только когда direct мёртв. Умно.
- **Транспорт: TCP + Reality + `xtls-rprx-vision`** (скорость), fp `firefox`. НЕ XHTTP (vs #1/#2) — ставка на скорость, маскировка держится на dest.
- **★ Reality dest: `rbc.ru` и `storage.yandex.net`** — РЕАЛЬНЫЕ РФ-домены топ-репутации (резолвятся). Косить под РБК/Яндекс → DPI не заблокит (не блокировать же РБК) и не спалит. **Лучший приём захода — берём.** (vs битый samsung #1 / низкореп own-домен #2.)
- **~14 экзитов** (US/CA/FR/DE/CH/PL/LT/FI/UK + рандом `.site/.online/.ru`), имена кодируют гео+хостера (m247, gthost, dp). Exit-домены публично **NXDOMAIN** — анти-харвест/ротация.
- **Продукт сегментирован** (скрин «Liberty VPN»): категории **Лучшие ⚡ / Зарубежная оплата 💳 / Для игр 🎮 / Белые списки**. Per-country + `bypass`-вариант с пингом (Испания 399ms / Испания bypass 783ms). Зрелый UX.
- **РЕАЛИТИ-ЧЕК чистоты:** upstream-мосты — `proxy:true` грязные IP на мелких AS (Латвия/НЛ, IT HOSTLINE, частный AS «Ivanov Vitaliy», похоже на лизинг/хайджек диапазонов; **креды/IP не логируем**). Exit-хостеры по именам — M247/GTHost/DataPacket (известные VPN-хостеры = засвеченные сети). **Даже самый рекламируемый сервис сидит на палёных IP** → отсюда «серверы отваливаются».
- **DNS:** только Google DoH. Роутинг: РФ (домены+`geosite:category-ru`+курированные `.com/.tech` РФ-сервисов: альфа/втб/тинькофф/моекс/озон/вб/яндекс-все-TLD…) → direct; bittorrent → direct (мимо VPN); остальное → балансер.

### Config 3-payment — Liberty «Зарубежная оплата 💳» (Индия bypass / Россия / Турция)
**Тест на главный вопрос — решён ли чистый IP даже в премиум-тире: НЕТ.**
- Технически идентичны #3 (VLESS+TCP+Reality+Vision, dest rbc.ru/storage.yandex.net, тот же РФ-роутинг). «Платёжный тир» — это не другой конфиг, а **отбор** определённых exit'ов в категорию.
- Все exit-домены публично **NXDOMAIN** (приватный резолв, анти-харвест) — прямо IP не вытащить.
- **Мост India-bypass `153.80.32.244` = `proxy:true`**, Франция, Host Telecom (мелкий AS214238). Назван «ru-upstream», но физически Франция — мосты раскиданы по ЕС (FR/LV/NL), не РФ, все грязные.
- **🇷🇺 exit = `ru-selectel-01.com`** → Selectel (легит РФ-облако), Reality-dest = свой сабдомен `sni.ru-selectel-01.com`. Под РФ-банкинг (нужен РФ-IP) — единственный осмысленный «чистоватый» выбор (легит домашнее облако под домашний кейс).
- **Юзер: «пинг единственный <1000 — Турция».** Премиум платёжный тир у лидера в основном **МЁРТВЫЙ** — отвечает 1 нода. Подтверждено: чистый живучий IP не решён даже у Liberty.

### Config 5 — «⚡ Самый быстрый» + «🛡️ Обход белых списков» (агрессивно рекламятся)
**Технически самый продвинутый. Два приёма, которых нет у других.**
- **Стратегия A («быстрый»):** VLESS+TCP+Reality+Vision, dest **`ru.tradingview.com`** (РФ-домашний, топ), fp firefox, авто-балансер. Ноды — netcup/Infrastructure Group (NL/DE/US, raw-IP). **★ ВПЕРВЫЕ `proxy:false`** — не «чистый резидент», а **свежий дата-центр, ещё не сожжённый** (netcup менее абьюзный, чем M247/GTHost). Всё ещё datacenter → AI Studio скорее всего режет, но уже лучше всех предыдущих.
- **★★ Стратегия B («обход белых списков») — главное открытие захода:** VLESS+**XHTTP+TLS, фронт за РОССИЙСКИМ CDN** (`*.begetcdn.cloud` = Beget, `*.trbcdn.net`). Трафик идёт на реальный домен РФ-CDN по настоящему TLS → выглядит как обычный CDN-кэш → **переживает даже whitelist-режим** (нельзя заблокить целиком домашний CDN). Частичное РЕШЕНИЕ проблемы IP: фронтясь за CDN, **берёшь взаймы репутацию CDN**, и собственный exit-IP перестаёт быть узким местом.
- **Экспертная обфускация XHTTP:** path `/assets/cache/`, паддинг под заголовок `X-Cache`, `seqKey=page` (под пагинацию), `sessionKey=X-Auth-Token` (под API), uplink методом `HEAD`. Косит под обычный CDN/API-трафик.
- **Whitelist-bypass роутинг:** AI (openai/claude/gemini/perplexity/mistral/copilot), YouTube/Twitch/Discord/WhatsApp/Signal → в CDN-тоннель; `geosite:whitelist`+`geoip:whitelist` → direct. Готовятся к «белому интернету».

## Карта обхода («какие адреса VPN игнорирует») — копим отсюда
**Эталон = Config 2** (зрелый курированный split, проверен месяцем эксплуатации). #1 — почти full-tunnel (плохо).
Это самое практичное: чужие routing-правила = их продуктовые решения, проверенные на живых юзерах.
- **Direct / в обход туннеля:**
  - AmoreSZI: только LAN/private (`10/8`, `172.16/12`, `192.168/16`, `169.254/16`, multicast) + Yandex-DoH `77.88.8.8:443`. **РФ-сайты НЕ выведены в direct** (минус: всё через грязный CH-exit).
- **Block (реклама/трекеры):**
  - AmoreSZI: blackhole-outbound есть, но правил block нет — рекламу не режут.
- **Force-proxy (всегда в туннель):**
  - AmoreSZI: Google-DoH `8.8.8.8:443` (чтобы DNS-запросы не утекали и не перехватывались).
- **DNS:**
  - AmoreSZI: DoH (Google+Yandex), `UseIPv4`, host-pinning РФ-госдоменов к реальным IP (анти-poisoning). Без fakeip.

## Приёмы к внедрению (ранжированно)
1. **Богатая Happ-интеграция через sub-заголовки** (AmoreSZI): `Announce`/`Profile-Title`/`Profile-Update-Interval`/`Profile-Web-Page-Url` → баннер, автообновление, брендинг и саппорт прямо в клиенте. Дёшево, заметно повышает «премиальность». Проверить, поддерживает ли это наша Marzneshin-отдача.
2. **Нода-сообщение вместо пустого конфига** при отсутствии доступа (AmoreSZI: «Не поддерживается») — юзер видит понятную причину, а не молчаливый фейл.
3. **Анти-скрейп: реальные ноды только «своим» форматам/клиентам**, иначе болванка `0.0.0.0` — бережёт IP от парсеров/блокировщиков.
4. **XHTTP-транспорт** (VLESS+XHTTP+Reality) — современный, ходит и напрямую, и через CDN, рвёт upload на POST-чанки (стойко к DPI). Оценить: предлагаем ли мы XHTTP-вариант (vs наш текущий транспорт).
5. **DNS-дисциплина:** иностранный DoH → в туннель (анти-лик), РФ-DoH (Yandex) → direct (скорость), `UseIPv4`, прибивка критичных РФ-госдоменов к реальным IP (анти-poisoning). Берём — и делаем лучше: РФ-госуслуги/банки ещё и в **direct** по роутингу, а не только в DNS.
6. **★ Зрелый split-tunnel (из #2) — копировать целиком:** РФ (банки/гос/маркетплейсы/телеком/стриминг) → direct; заблок. в РФ (AI/соцсети/YouTube/Telegram + IP-блоки TG) → force-proxy; bittorrent → block. Самый ценный трофей — готовая проверенная «карта обхода».
7. **XHTTP анти-DPI тюнинг (из #2):** `xPaddingBytes 100-1000`, рандом-`scStreamUpServerSecs`, `xmux` с рандом-реюзом, path под app-API (`/api/v2/updates`). Трафик косит под обычный keep-alive HTTP.
8. **Блок bittorrent на выходе** — защита exit-IP от абуз-жалоб, продлевает жизнь IP.
9. **★★ RU-domestic Reality dest (из #3):** косить под `rbc.ru`/`storage.yandex.net`/vk/mail — РФ-домены топ-репутации. Нельзя заблокировать (не рубить же РБК/Яндекс) и не палится. **НЕ использовать AI-дефолты** (samsung/microsoft/apple) — Claude и гайды по 3x-ui советуют их всем → они стали общим паттерном → DPI может фингерпринтить именно их. (Кривой «samsumg» у #1 — ровно отсюда, AI-дефолт + опечатка.)
10. **Авто-балансер (из #3):** health-check `gstatic/204`, `leastLoad`, штраф на bypass → авто-предпочтение быстрого direct, фолбэк на цепочку при блоке. Прозрачно вместо ручного «переключаюсь, т.к. отвалилось».
11. **Сегментация серверов по задаче (из #3):** «Зарубежная оплата / Для игр / Белые списки» — чистые IP под платежи, низкий пинг под игры.
12. **Эфемерные/нерезолвящиеся exit-домены** (#3 публично NXDOMAIN) — анти-харвест exit-IP.
13. **★★★ КЛЮЧЕВОЕ — «надеть одежду домашнего облака».** Оба топа сошлись на одном ответе:
    - **Liberty (whitelist):** exit ПРЯМО на **Yandex.Cloud** (`188.72.103.3`, AS Yandex.Cloud, **`proxy:false`**) + TLS-SNI `cdn.tracker.yandex.net` (реальный Yandex CDN) → трафик неотличим от легитимного Yandex, **заблокить нельзя без сноса Yandex Cloud**, переживает whitelist. Маршрут построен как «decoy (Reality) + fallback на Yandex-route».
    - **#5:** фронт XHTTP+TLS за Beget CDN (`*.begetcdn.cloud`).
    **Это и есть настоящий ответ на проблему чистого IP: не «купить резидентские IP», а ХОСТИТЬСЯ внутри доверенного РФ-облака (Yandex/VK/Selectel) и носить его SNI.** Минус — РФ-юрисдикция/риск бана аккаунта (Liberty смягчает регионом **Yandex Cloud Dubai**: репутация Yandex, юрисдикция ОАЭ). Это north star нашего рва.
14. **Свежее, менее абьюзное хостинг (из #5):** netcup → `proxy:false` (ещё не сожжён, в отличие от M247/GTHost). Не «чистый», но оттягивает флаг.
15. **«Обход белых списков» как продукт-фича (из #5):** отдельный профиль под сценарий РФ-«белого интернета» (всё запрещённое → за CDN-фронт). Дальновидно + продаётся как страховка.

## Стек конкурентов (панели + хостинг)
- AmoreSZI → **Remnawave** (Caddy). Сравнить с нашей Marzneshin: фичи, sub-шаблоны, happ-поддержка.
- **G-VPN → ТОТ ЖЕ Remnawave-кит, что AmoreSZI** (идентичный шаблон: DNS-hosts, inbounds, nalog-пиннинг, роутинг — побайтово). Вывод: есть **реселл-рынок «VPN-в-коробке»** — панель Remnawave + купленные ноды = мгновенный «бренд». Половина «конкурентов» в РФ-телеге = один кит под разными наклейками. **Барьер входа ≈ ноль** → ещё одно доказательство, что отличие не в софте, а в IP.
- **Хостинг-лиды (валидированы выживанием Liberty ≥6 мес):** мосты/exit на M247, GTHost, DataPacket, латвийский IT HOSTLINE (AS44559), мелкие частные AS (LV/NL). ВСЕ `proxy:true`.
- **Важный вывод про Liberty:** живёт НЕ за счёт чистых IP, а за счёт **ротации + маскировки (РФ-dest) + балансера на грязных IP** = стратегия **B**. Наш ров — стратегия **A** (чистые IP, держащие AI Studio, живут долго). Латвия/НЛ как локации моста — на заметку (рабочие для grey-стратегии), но это не «чистые» локации.
- **Открытый вопрос:** решил ли клин-IP хоть кто-то даже для премиум-тира? → проверить их сервер «Зарубежная оплата» на AI Studio (там их предположительно самые чистые IP).

## Уже есть у нас / у нас лучше (где бьём AmoreSZI)
1. **Чистота exit-IP.** У них `103.227.84.107` = `proxy:true` → AI Studio/ChatGPT/банкинг падают. Наш козырь: экзиты, проходящие AI Studio (см. [[feedback_exit_quality_aistudio_test]]). Проверяемо и продаётся.
2. **Reality dest.** У них битый `www.samsumg.com` (REFUSED) → палевно. У нас — реальный популярный резолвящийся РФ-доступный домен.
3. **РФ-сайты.** Они гонят всё через швейцарский exit (full-tunnel) → РФ-банкинг/госуслуги видят иностранный IP и ломаются (их nalog-пиннинг полудохлый). Наша цепочка (РФ-бридж → иностранный exit) + правильный split → РФ-сайты быстрые и «родные». Большой отрыв.
4. **★ ГЛАВНОЕ — чистота и ЖИВУЧЕСТЬ exit-IP.** Оба конкурента (#1 и #2) — `proxy:true`, оба валят AI Studio, у обоих ноды дохнут (юзер: «1-2 работают, постоянно переключаюсь»). Конфиг/транспорт у всех уже одинаков и решён (VLESS+XHTTP/TCP+Reality) — **единственная нерешённая отраслевая проблема: держать чистые рабочие exit-IP живыми.** Это и есть наш ров: clean-IP (proxy:false, проходят AI Studio) + быстрая ротация ([[project_vpn_chain_architecture]], [[project_vpn_hoster_shortlist]]).
5. **★★ РЕАЛИТИ-ЧЕК: чистый IP не решил НИКТО — даже Liberty (#3, самый рекламируемый).** Архитектуру (цепочка+балансер+РФ-dest) они вылизали, но мосты и exit — на `proxy:true` грязных/лизинговых IP (LV/NL, M247/GTHost), ноды ротируют. **Долговечный чистый IP остаётся нерешённым у всех** → наш ров не только реален, но и **greenfield**. Их категория «Зарубежная оплата» — намёк, что горстку чистых держат под платежи; её и переплюнуть. Чертёж backend'а = конфиг #3. **ПОДТВЕРЖДЕНО платёжным тиром:** мост `proxy:true` (FR), exit'ы NXDOMAIN, тир в основном мёртвый (отвечает 1 нода <1000ms). Чистый живучий IP не решён НИКЕМ, включая лидера — поляна полностью наша.

## ИТОГ разбора (4 сервиса)
**Два тира конкурентов:**
- **Реселл-кит** (AmoreSZI, G-VPN): один Remnawave-шаблон, 1-2 ноды, битые/нерезолвящиеся Reality-dest, Happ-lock. Коммодити, барьер ≈ 0.
- **Серьёзные** (#2 «DE», Liberty): экспертный XHTTP-тюнинг ИЛИ цепочка+балансер, РФ-домашние реальные dest, курированный роутинг, зрелый продукт.

**Универсально для ВСЕХ:** отличные конфиги + грязные `proxy:true` IP + ноды дохнут/ротируют. Даже платёжный тир лидера в основном мёртвый.

**Вывод:**
1. «Сделать VPN» = коммодити (реселл-киты доказывают; запуск бренда — выходные).
2. Узкое место у всех = чистые живучие IP. И **ОТВЕТ нашёлся** у топов: хостятся внутри РФ-облаков (Yandex Cloud → `proxy:false`) и фронтят SNI под их CDN → неотличимо от Yandex, нельзя заблокить, переживает whitelist. Технический north star рва — не «резидентские IP», а **«одежда домашнего облака»** (минус — РФ-юрисдикция, смягчается зарубежными регионами тех же облаков). Два под-вопроса: (а) не быть заблокированным в РФ — решает домашнее-облако-фронт; (б) проходить иностранные анти-VPN (AI Studio) — нужен чистый egress. Наша цепочка (домашний фронт-вход → чистый выход) закрывает оба.
3. Ров PRSLOY = **clean-IP сорсинг + живучесть**. Остальное (стек/цепочка/балансер/dest/роутинг) — копируется из этой доки за дни.
4. Это ровно слой, где слился партнёр → правильно забрать backend под себя ([[project_investor_readiness_open_items]]). R&D-цель: где брать чистые IP и как держать их до флага.
